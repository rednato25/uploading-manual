## Comparing discs and editions

- [blu-ray.com](https://www.blu-ray.com/): Every disc release, specs and reviews.
- [DVDCompare](https://www.dvdcompare.net/): Runtimes, cuts, audio and subtitle tracks per edition.
- [caps-a-holic](https://caps-a-holic.com/): Screenshot comparisons between discs.
- [slow.pics](https://slow.pics/): Your own screenshot comparisons, source against encode.

## Release names and history

- [srrdb](https://www.srrdb.com/): The original name of a scene release.
- [predb.me](https://predb.me/): When a scene release came out.
- [TRaSH Guides](https://trash-guides.info/): Naming in Radarr and Sonarr, and what release tags mean.

## Learning more about encoding

- [Doom9 forum](https://forum.doom9.org/): The long-running forum on encoding.
- [x264 settings reference](https://en.wikibooks.org/wiki/MeGUI/x264_Settings): What each x264 setting does.
- [x265 documentation](https://x265.readthedocs.io/): Every x265 option.

## Software

- [MediaInfo](https://mediaarea.net/en/MediaInfo): Reading files.
- [MakeMKV](https://www.makemkv.com/): Ripping discs.
- [MKVToolNix](https://mkvtoolnix.download/): Editing MKV files.
- [StaxRip](https://github.com/staxrip/staxrip): Encoding on Windows.
- [Subtitle Edit](https://www.nikse.dk/subtitleedit): Subtitles.
- [Upload Assistant](https://github.com/Audionut/Upload-Assistant): Uploading.
- [qBittorrent](https://www.qbittorrent.org/): Seeding.

## Old advice to ignore

<GoodBad goodLabel="Do" badLabel="Old advice">
  <ul slot="good">
    <li>Run a test encode for every film.</li>
    <li>Use 2-pass when you need a set size.</li>
    <li>Leave denoise and deband off on a clean remux.</li>
    <li>Use a release encoder the trackers accept.</li>
  </ul>
  <ul slot="bad">
    <li>HandBrake for release encodes. Several trackers reject or discourage it.</li>
    <li>A fixed CRF or bitrate for every film. Every film compresses differently. Run a test encode.</li>
    <li>Denoise and deband filters by default. On a clean remux they remove detail and grain.</li>
    <li>1-pass ABR "because it hits the size". 2-pass hits the size too, and spends the bits better.</li>
  </ul>
</GoodBad>
