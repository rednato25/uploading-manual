## Who this is for

Anyone about to start an x264 or x265 encode who has not yet picked the preset and CRF. **CRF** (constant rate factor) is the quality target: lower means better quality and a bigger file. The **preset** is how hard the encoder works: slower presets take longer and usually save bits.

## When you use this

Before every encode of a new source. Grain, darkness and motion change what a CRF gives you, so a value from another film is only a starting point.

## Before you start

- The source, usually a remux
- [ffmpeg](https://ffmpeg.org/) 5.1 or newer. Check with `ffmpeg -version`. The frame-grab command in step 5 needs 5.1 or newer.
- MediaInfo
- Your crop values, if you will crop. Every test uses the same crop as the final encode.

## Steps

<Steps>

1. **Cut the sample.** Pick a busy part of the film: faces, dark scenes, grain or fast motion. This cuts about 90 seconds starting at 30 minutes, video only, without re-encoding:

   ```bash wrap
   ffmpeg -ss 00:30:00 -i source.mkv -t 90 -map 0:v:0 -c copy sample.mkv
   ```

   The cut starts at the keyframe before `-ss`, so the sample can be a few seconds longer than 90. Read its real length in MediaInfo.

2. **Encode the sample with two or three presets.** Keep the CRF and tune the same. Audio is off (`-an`), so the size is video only:

   ```bash wrap
   ffmpeg -i sample.mkv -map 0:v:0 -an -c:v libx264 -preset slow -crf 18 -tune film test-slow.mkv
   ffmpeg -i sample.mkv -map 0:v:0 -an -c:v libx264 -preset slower -crf 18 -tune film test-slower.mkv
   ffmpeg -i sample.mkv -map 0:v:0 -an -c:v libx264 -preset veryslow -crf 18 -tune film test-veryslow.mkv
   ```

   If you crop, add the same crop to each command, for example `-vf crop=1920:800:0:140`. For x265, use `-c:v libx265` and leave out `-tune film`, which x265 does not have.

3. **Write down the numbers.** For each file: the size in MB, the fps and the time from ffmpeg's last progress line. Work out the bitrate as in [Reading the result](#reading-the-result).

4. **If a slower preset came out larger, test it again one CRF higher.** For example, `-crf 19` instead of 18. Now the files are close in size, and the frames show which preset uses the bits better.

5. **Grab the same frames from each file.** Pick three to five frame numbers. This saves frames 300, 1200 and 2000 as PNG:

   ```bash wrap
   ffmpeg -i test-slow.mkv -vf "select='eq(n\,300)+eq(n\,1200)+eq(n\,2000)'" -fps_mode passthrough -frames:v 3 slow-%02d.png
   ```

   Run it on every test file with the same numbers, and change the output name each time. `-fps_mode` needs ffmpeg 5.1 or newer. Grab the same frames from `sample.mkv` to have the source next to them.

6. **Compare on slow.pics.** On [slow.pics](https://slow.pics/), make a new comparison and upload the frames, one group per frame number. Name each image after its file (source, slow, slower). Flip between them on faces, grain, dark areas and edges.

7. **Pick.** Take the slowest preset you can afford in time that looks as good as or better than the others. Use its CRF for the full encode.

</Steps>

All test files come from the same sample, so frame 1200 is the same picture in each. Two releases from different sources are often not aligned: the same frame number shows a different picture. For those, a tool called Pear can line them up.

The bitrate is a guess for the whole film. A sample from a busy scene usually runs higher than the average.

## Stop and ask someone if

- Every preset still looks clearly worse than the source after you lower the CRF by 2.
- The sample length in MediaInfo is far from what you cut.
- The frames from two test files show different pictures at the same frame number.
